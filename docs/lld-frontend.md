# Frontend low-level design

ExpenseFlow web app in `frontend/`. React 19 + Vite + TypeScript, TanStack Router (file-based) and
TanStack Query, Zod schemas mirroring `docs/openapi.json` (the contract wins on any conflict),
react-hook-form, shadcn/ui on Base UI with Phosphor icons, Tailwind v4, MSW mocks, Vitest +
Testing Library, Playwright. Package manager: pnpm 11.16.

## 1. Folder structure

```
frontend/
  src/
    main.tsx                 entry: optional MSW worker in dev, QueryClient, router
    router.tsx               createAppRouter(queryClient, options) - context { queryClient }
    routeTree.gen.ts         generated by the TanStack Router Vite plugin (do not edit)
    routes/                  file-based routes
      __root.tsx, index.tsx (/ -> /dashboard), login.tsx
      _authed.tsx            pathless guard layout (AppShell)
      _authed/               every signed-in screen (see section 6)
      -*.test.tsx            route-level tests ("-" prefix = ignored by the router)
    features/<feature>/
      api.ts                 Zod schemas, types, query options, query keys, mutations
      components/            screen components owned by that feature
      (features: admin, approvals, audit, auth, claims, insights, payouts)
    components/
      app-shell.tsx          sidebar per role (NAV_BY_ROLE), user menu, sign out
      status-chip.tsx        claim status badge
      ui/                    shadcn components (button, table, dialog, sheet, select, ...)
    lib/
      api.ts                 apiRequest, apiBlob, ApiError, errorMessage
      query-client.ts        createQueryClient (staleTime 60s, retry 1, no refetch on focus)
      format.ts              en-IN currency/date formatters
      utils.ts               cn() = clsx + tailwind-merge
    mocks/
      handlers/<feature>.ts  MSW handlers per feature; handlers/index.ts merges them
      data.ts                seeded fixtures (@faker-js/faker)
      browser.ts / node.ts   MSW worker (dev) / server (Vitest)
    test/
      setup.ts               MSW server, matchMedia polyfill, asyncUtilTimeout 3000
      render.tsx             renderRoute(url) helper
  e2e/                       Playwright specs: app.spec.ts, flows.spec.ts
  nginx.conf, Dockerfile     production image (section 12)
```

`insights` keeps its API in `features/insights/summary-api.ts` (no `components/` folder; the screen
lives in `routes/_authed/insights.tsx`).

## 2. Routing and guards

- **`/_authed` (`src/routes/_authed.tsx`)** - `beforeLoad` calls `loadSession(queryClient)`.
  No user -> `redirect({ to: '/login', search: { redirect: location.href } })`. Otherwise returns
  `{ user }` into route context, and the layout renders `<AppShell user>` around `<Outlet />`.
- **`loadSession` (`features/auth/session.ts`)** - no token -> `null`. Otherwise
  `queryClient.ensureQueryData(meQueryOptions)` (`GET /auth/me`, key `['auth','me']`). Any error
  clears the token and the cached `me`, returns `null`.
- **`/login`** - `validateSearch` accepts `redirect?: string`. A signed-in visitor is redirected
  immediately. After sign-in: `safeRedirect(redirect) ?? roleHome(user.role)`.
- **`safeRedirect`** accepts only paths starting with `/` and not `//` (no off-site redirects).
- **Role home (`ROLE_HOME`)**: employee -> `/claims`; line_manager, finance_auditor,
  finance_head -> `/approvals`. `/` and `/dashboard` both forward there.
- **Per-role screens**: the sidebar (`NAV_BY_ROLE` in `components/app-shell.tsx`) only shows
  screens for the role. Screens also check `user.role` from route context (e.g. People shows a
  not-allowed state for non finance heads; policy rules are read-only unless finance head).
  The API enforces roles regardless (403).

## 3. Data layer (`src/lib/api.ts`)

- **`apiRequest<T>(path, { method, body, schema })`** - prefixes `/api/v1`, sets
  `Accept: application/json`, `Content-Type: application/json` for JSON bodies (not for
  `FormData`), and `Authorization: Bearer <token>` when a token is stored. Parses the response with
  the Zod `schema` (204 -> `schema.parse(undefined)`). A response that does not match the schema
  throws, so contract drift is loud (that is how D4, the audit event shape change, surfaced).
- **`apiBlob(path)`** - same auth and error handling, returns a `Blob` (receipts, payout export).
- **`ApiError`** - `status`, `code`, `message`, `fields: { field, message }[]`, built from the
  backend envelope `{ error: { code, message, details?: { fields? } } }`. Non-envelope failures
  become `code: 'http_error'`.
- **`errorMessage(err)`** - user-facing text; appends `field: message` pairs for 422s.
- **Query keys** (per feature, in `api.ts`):
  - `claimKeys.all = ['claims']`, `claimKeys.list(params)`, `claimKeys.detail(id) = ['claims','detail',id]`,
    plus `policyResults(id)`, `audit(id)`, `steps(id)`, `comments(id)` under the detail key.
  - `approvalKeys.pending({limit, offset}) = ['approvals','pending',...]`, `approvalKeys.delegations = ['delegations','me']`.
  - `adminKeys.rules(includeInactive)`, `adminKeys.users`; `payoutKeys.*`; `auditKeys.search(...)`;
    dashboard `['dashboard','summary', month]`; auth `['auth','me']`.
- **Invalidation** - prefix-based after mutations: approve/reject/send back invalidate
  `['claims']` and `['approvals']`; claim save invalidates `['claims']`; comment invalidates
  that claim's comments and audit; delegation create/cancel invalidates `['delegations','me']` and
  `['approvals']`; payout batch creation invalidates `payoutKeys.all` and `['claims']`; person/rule
  edits invalidate `adminKeys.users` / `['policy-rules']`.

## 4. Auth and session

- Token in `localStorage` key `expenseflow.access_token` (`features/auth/token-storage.ts`); all
  access wrapped in try/catch (private mode -> treated as no token).
- Login: `POST /auth/login` with `{ username, password }`; the field is labelled "Work email" and the
  API accepts username or email (case-insensitive).
- 401 handling: in `send()`, a 401 while a token was sent clears the token. The next route load
  then finds no session and redirects to `/login?redirect=...`.
- Sign out (`signOut`): clear token and `queryClient.clear()`.

## 5. Mocks

Dev requests go to the real API through the Vite proxy (`/api` -> `http://localhost:8000`, or
`VITE_API_PROXY_TARGET`). With `VITE_ENABLE_MOCKS=true`, `main.tsx` starts the MSW worker first.
Vitest and Playwright always use mocks.

## 7. Forms

- react-hook-form + `zodResolver` everywhere (login, claim form, add person, delegation).
- Claim form uses two schemas: `baseSchema` for draft save (fields optional) and `submitSchema` for
  submit (required fields, receipt rules); the resolver picks by mode. Lines via `useFieldArray`
  (max 50).
- Null optional fields are dropped before sending (workaround for D1; the API now returns 422).
- **Server 422 mapping**: on error, `form.setError('root', errorMessage(err))`; then each
  `ApiError.fields` item matching `lines.N.<name>` goes to `lines.N.<name>`, and `title` to `title`,
  so the message shows under the input.
- Other forms show `errorMessage` as a root error; delegation adds a client check (no self-delegation).

## 8. Receipt viewer (`features/claims/components/detail/receipt-viewer.tsx`)

Receipts are protected, so a plain `<img src>` cannot send the bearer token. The viewer runs a
query (`['claims','detail',claimId,'attachment',id]`, `staleTime: Infinity`) calling
`downloadAttachment` -> `apiBlob`, then `URL.createObjectURL(blob)` in an effect and
`URL.revokeObjectURL` in its cleanup. Content type comes from the blob, falling back to the
attachment's `content_type`. Payout CSV export uses the same blob -> object URL -> download pattern.

## 9. Bulk approve (`features/approvals/components/approvals-queue.tsx`)

There is no bulk endpoint. `approveSelected()` loops over the selected rows **sequentially**,
calling `approveClaim(claim.id, { step_id: step.id })` for each, updating a progress counter,
collecting failures. Then one toast: "Approved X of N" (error toast lists each failed claim ref
and message), clears the selection, and invalidates `['approvals']` and `['claims']`. Filters on
the queue are client-side; changing page clears the selection.

## 10. Testing seams

- **MSW per feature**: `src/mocks/handlers/{auth,claims,approvals,admin,payouts,audit-logs,dashboard}.ts`,
  merged in `handlers/index.ts`. Vitest server runs with `onUnhandledFrame: 'error'`, so a request
  with no handler fails the test. Tests override with `server.use(...)` per case.
- **`renderRoute(url)`** (`src/test/render.tsx`): full app with in-memory history at `url`, fresh
  QueryClient with `retry: false`. Route tests live in `src/routes/-<screen>.test.tsx`.
- `src/test/setup.ts`: `window.matchMedia` polyfill for sonner (D5); `asyncUtilTimeout: 3000` (D6).
- **E2E** (`e2e/`, `playwright.config.ts`): own dev server on port 5174 with `VITE_ENABLE_MOCKS=true`
  (never reuses a `pnpm dev` on 5173); `retries: 2` in CI.
- Commands (in `frontend/`): `pnpm lint`, `pnpm format:check`, `pnpm test:run`, `pnpm build`,
  `pnpm test:e2e`, `pnpm audit --prod --audit-level high`.

## 11. Conventions

- `@/` alias -> `src/`. Line endings LF (`frontend/.gitattributes`; Prettier's default `endOfLine` is `lf`).
- `cn` comes from `src/lib/utils.ts` (clsx + tailwind-merge); the shadcn CLI may rewrite it to a
  bogus `cn` package - revert if so.
- `routeTree.gen.ts` is regenerated by the Vite plugin on `pnpm dev`, `pnpm build` or Vitest; a stale
  one can break `tsc -b` (D10).

## 12. Build and deploy

- `pnpm build` = `tsc -b && vite build` -> `dist/`.
- `frontend/Dockerfile`: stage 1 `node:26.13.1-alpine`, `npm install --global pnpm@11.16.0`,
  `pnpm install --frozen-lockfile`, `pnpm build`. Stage 2 `nginx:1.29-alpine` with `nginx.conf` and
  `dist/`; HEALTHCHECK `wget --spider http://127.0.0.1/`.
- `frontend/nginx.conf`: `/api/` proxied to `api:8000` (same-origin, no CORS; `proxy_read_timeout 60s`);
  `/assets/` cached 1 year (immutable, hashed names); everything else
  `try_files $uri $uri/ /index.html` with `Cache-Control: no-cache` (SPA fallback);
  `client_max_body_size 6m` (API receipt limit is 5 MB).
- Compose service `web` publishes `8080:80` and starts after `api` is healthy. Rebuild: `docker compose up -d --build web`.
- CI (`.github/workflows/ci.yml`, pull requests only): `web` job runs lint, format check, Vitest,
  build, and `pnpm audit`. Playwright is not run in CI.
